# 活动取消补办管理

本项目维护活动取消补办管理的领域约定、角色边界与样例数据，供后端服务、接口和自动化验证统一使用。当前契约覆盖活动统筹员、讲解员、学校联系人、场馆管理员，并明确取消补办关联、参与者原子迁移、多次改期版本、统计关系去重等关键约束。

## 目录

- `domain/contract.json`：领域角色、状态、约束和样例。
- `src/domain_contract/`：契约读取与确定性校验。
- `src/makeup_service/`：取消-补办后端服务（领域模型、原子转移、报表与查询接口）。
- `tools/check_contract.py`：命令行摘要检查。
- `tools/demo_makeup.py`：端到端演示（取消 → 补办 → 改期 → 报表与归属）。
- `tools/run_api.py`：只读查询接口（标准库 HTTP，零依赖）。
- `tests/`：契约完整性与领域规则回归测试。

## 后端服务（src/makeup_service/）

针对"场馆临时停用 → 学校场次取消 → 客服另建补办活动"的场景，服务登记取消原因、原场次、可迁移预约、补办候选与通知状态，并在确认补办时原子转移参与者与有限资源，保证原签到、资源占用和通知都能沿补办关系关联。

### 确定规则

- **取消登记**：仅 筹备/待确认/已排定 的场次可取消；同一场次重复登记幂等返回原记录；登记后有效预约转为待迁移，并按学校生成取消通知。
- **确认补办（原子转移）**：所有写操作在同一把锁内"预检 → 应用"。资源按场次时段校验余量，不足则整体失败、不产生任何副作用；成功后参与者预约与资源占用一次性迁往补办场次，生成版本化补办关系（含迁移审计）。
- **重复确认**：相同幂等键或相同候选直接返回既有补办关系；已补办后确认其他候选抛错并提示走改期接口；并发确认只会产生一条补办关系。
- **多次改期**：每次改期生成版本 +1 的新补办关系，参与者与资源整体迁往新场次，旧场次与旧关系被取代，仅最新版本生效；补办场次已开始（执行中/已结算）则拒绝改期。
- **原场次恢复**：未补办直接恢复（预约回有效、候选作废）；已补办且补办场次未开始则参与者与资源整体迁回原场次、补办关系撤销；补办场次已开始则恢复窗口关闭，拒绝恢复。恢复后再次取消会生成新的取消单。
- **部分学生退出**：退出即终态并留痕，迁移时自动排除；确认前退出不计入迁移，确认后退出从补办场次移除；场次已开始不可退出，重复退出报错。
- **报表去重**：按补办关系把原场次与各版补办场次串成链，每条链只按最终生效场次（已恢复取原场次、已补办取最新生效版本、未补办记已取消）统计一次，杜绝取消与补办重复计入完成量。
- **参与者最终归属**：沿预约血缘链取每个参与者的最终状态——已归属（含场次与状态）/ 待安置（已取消未补办）/ 已退出。

### 查询接口

`MakeupAPI` 提供 JSON 可序列化视图；`tools/run_api.py` 以标准库 HTTP 暴露：

- `GET /api/attributions`、`GET /api/attributions/<id>`：每个参与者最终归属。
- `GET /api/reports/completion`：按补办关系去重的完成量报表。
- `GET /api/cancellations/<id>`：取消单全景（原因、原场次、可迁移预约、候选、补办关系、通知状态）。

启动示例：`python3 tools/run_api.py --port 8000 --seed-demo`
